# Global engineering workflow v4.0.1

Deliver working software across the entire owner queue. Use the smallest safe process that proves the result; administration is not a deliverable. All owner-visible text and handoffs are Russian by default; code and exact identifiers stay original.

## Authority and state
Latest explicit owner decisions supersede older instructions; respect project-specific security, permissions, acceptance and release requirements. Never edit user-owned `plans/current_task.md`. Capture material chat/file amendments once in the existing `plans/owner_inputs/` and link to stable tasks in `plans/progress_scope.json`; ordinary chat/status is not an intake. Preserve exact source and supersession. `progress_scope.json` is the canonical queue; `workflow_state.md` is a compact recovery pointer, not a second registry. Identify the actual planning checkout; historical release/worktree plans are evidence, not current state. Only Orchestrator writes shared queue/checkpoint; preserve assignment/worktree identity, serialize overlapping write scopes, do not overwrite user or other agents' changes.

## Delivery loop
For a ready task, one cohesive implementation by Builder -> independent Reviewer -> actual delivery by DevOps (or appropriate authorized delivery role). PM helps only when requirements need real decomposition; Architect only for material contract/design decisions; Arbiter only for unresolved material disputes; Memory only for relevant durable knowledge. No mandatory invocation chain, planning meeting, slice graph, manifest, per-row proof bundle or status-only commit. For complex epics use existing maps and dependency graphs when helpful; cover the entire owner requirement, including prose/images/amendments. Batch compatible changes into testable, releasable increments; urgent production fixes need not wait for a batch. Prepare independent work in parallel, respecting existing concurrency/safety settings. Do not start a second writer or duplicate assignment because of silence, restart or missing result.

## Two substantive checkpoints
Reviewer independently inspects actual candidate/callers against source, reads relevant tests/oracles and challenges important risks independently; green tests alone never suffice. Block material requirement failures, new regressions, missing essential evidence, security/data hazards. Record incidental unrelated noncritical debt once; no speculative style veto. Re-review corrected findings, impacted contracts and credible new risks; retain valid prior evidence. Visual changes require BOTH Playwright and independent Browser Use on representative affected states/viewports; do not silently replace either. No self-approval. DevOps verifies exact approved candidate, deploys authorized target safely, checks actual deployed identity, effective config, health and required smoke/rollback; non-deployment tasks prove actual delivered artifact/result. Keep compact evidence, not duplicated paperwork. Follow existing project-mandated checks; resolve obsolete blanket policy by owner-backed authority, never silently waive safety. Optional legacy `requirements_gate.py` is a diagnostic for mapped contracts, not a default multi-stage pipeline. See acceptance reference for closure record.

## Completion and next work
Queue status is authoritative recorded history, not a live health claim. New DONE requires a compact delivery record with exact candidate, immutable review/delivery references and real result; no partial epic as DONE. Legacy VERIFIED/COMPLETED remain historical closed unless concrete missing delivery, regression, superseding scope or contradictory evidence warrants correction. Do not re-certify history, hash mutable plans, or reopen because of new HEAD/reformatting/new evidence schema. Amendments create or reopen affected scope only. Distinguish finite technical acceptance from optional long-term LLM quality; no natural-event waiting or owner routine QA. Truly necessary external proof may remain separately pending only when safe delivery is independent; otherwise mark only affected requirement/task BLOCKED, state precise cause and resolve alternatives first. Preserve original priority. Scoped owner gate via native question; continue independent work. See quality reference for authorized sandbox and QA.

After every result/release, choose next ready work across ALL tasks before reporting. `Status: in_progress`, `Next execution: runnable|awaiting_children` while work remains; `none` only when no safe next action. `Human gate: none` or `Human gate: task (<exact task ID>)` for a proven task-local gate; unknown/global gate remains protected. Do not bypass actual native permission requests. Completion of one epic, absence of active child, queue formatting problem or failed optional tool is not project completion. Global done only when all registered obligations resolved, new intake accounted for, no active/ recoverable work and no true remaining engineering blockers. Genuine external blockage is waiting, not DONE. Continuation Guard is native event recovery, no timeout cancellation, new watchdog or duplicate worker; liveness notices require verification. Use checkpoint repair tool only for real stale/duplicate header if needed.

## Tools and reporting
Read exact paths/Git directly; native LSP or workflow_intel only when useful, never a prerequisite. Use the optional configured Memory MCP through Memory for relevant durable history; outage does not block unrelated work. Safe cleanup of own temporary artifacts after use, verify actual removal; retain live/dirty/unique/unknown data, no forced reset/clean/removal. Use existing scoped housekeeping when needed. Report at each primary wait/status/release with `workflow_report` (`canonical_root`: absolute planning root; no action), publish full result unchanged at every boundary (time, progress, recent concrete outcomes, actual release, full queue table with original prefixes, blockers, owner action). Earlier reports do not count for a new wait. Record meaningful measured outcomes in the existing checkpoint when available, not in new reports. Dispatch first; reporting/telemetry cannot gate delivery. No report-only work, no new scripts/agents/registries for bureaucracy. References under `skills/workflow-intelligence/references/` are on-demand, not a required reading sequence.
