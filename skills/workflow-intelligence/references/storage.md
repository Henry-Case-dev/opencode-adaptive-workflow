# Storage and cleanup (on demand)
Use existing WorkspaceData, managed scratch and worktrees. Reuse same checkout on retries; preserve isolated write scopes, evidence, unique commits and actual consumers. Avoid repo/dependency copies. Existing `workflow_housekeeping.py` provides inventory, allocation, registration, run-close, unit-close/unit-check, shared-scratch-close and epic-close. Use `--help` for actual parameters; preview before destructive action. No age/size/name based deletion, no forced worktree removal, no git reset/clean/stash of other work, no deleting unknown/user data, DBs, backups, credentials, required evidence or active/dirty/unmerged unique state. Keep branch/ref if removing a clean idle checkout. Never use local housekeeping on production.

After a check/unit, remove exact verified disposable outputs once consumers stop and necessary evidence is preserved. Use `run-close` for allocated runs; `unit-close --repo <root> --epic <id> --unit <id> --confirmed-idle --confirmed-evidence --apply` only when those facts are true; `unit-check` checks actual paths. A preview, green test, exit status, or `handoff_accounted` is not actual deletion; verify file absence and `cleanup_complete`. For external/native spill inspect actual generated paths and ownership. If retained, record exact path/reason/owner/next event in existing handoff, not a new ledger; no separate approval gate. Independent delivery proceeds if retained storage does not create actual risk. Use `--retention-file` if existing handoff has `cleanup_retained` entries. On recovery or low disk inspect actual space, inventory only relevant roots (`--sizes` only when needed); clean known safe outputs first. Unknown old/unmarked directories are inventory-only until proven safe. Shared cache only after all consumers idle; preserve reusable cache where valuable. Residual epic cleanup is not substitute for deleting per-task garbage. No additional cleanup subagent, scripts or daemon.
