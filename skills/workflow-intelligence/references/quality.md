# Practical QA and safe verification

Define observable success from owner contract before trusting implementation. Choose risk-driven equivalence classes, boundaries, decision tables, state transitions, normal/error/empty paths, concurrency, retries/restarts, authorization, data integrity and side effects. Test through real entrypoints, using independent expected values; isolate nondeterministic dependencies at genuine boundaries, never mock the behavior claimed. A nonempty result, no exception, source-text match, identical output from same algorithm, mocked call count or green coverage alone is not functional proof. For regressions use RED/GREEN or targeted negative control where feasible; important tests must distinguish wrong from correct. No mutation quota, arbitrary count or identical test per requirement. A passing test that cannot detect the original defect is not proof of that fix.

Builder searches existing tests by behavior/seam first; extend or consolidate when possible. Keep durable CONTRACT/REGRESSION/INTEGRATION intent near meaningful tests using existing TEST-LIFECYCLE convention when useful; PROVISIONAL diagnostic probes remove/promote. No bulk retrofit, per-test paperwork or registry. Tests of whole-file hashes, changing versions, internal function names, snapshots, arbitrary exact counts or implementation structure are justified only by an actual stable contract/security invariant. Otherwise test behavior: route authorization and API response instead of routes.py hash; version agreement across actual surfaces instead of literal version per test. Do not re-pin just to make green. Retire only proved obsolete/duplicate tests with preserved meaningful coverage. Never weaken assertions, hide skip/xfail or retry flakes into green. Keep actual security, data, migration and historical regression cases. Distinguish confirmed pre-existing failures from candidate regressions; disclose baseline, impact and why a nonblocking failure is unrelated, not mark it passed.

Reviewer reads actual code/callers, source, risk-relevant assertions and fixtures, including added/changed/deleted tests. Inspect independent oracle, actual runtime branch, meaningful failure and state/side effects; verify actual exit/collection/skip results and candidate. Independently exercise a relevant counterexample, negative control or exploratory path; choose proof proportionate to risk, static only for static claim. Green CI or another LLM is not approval. Real defects and essential proof gaps block; use early rejection for material finding; after correction re-check fixed issue/affected contracts/new risks, not all unchanged paths. Do not edit or self-approve. UI changes require both Playwright and Browser Use for representative affected views/states, not unrelated routes. Optional OCR delegation only if installed/authorized; verify exact base/candidate and exclusions, not separate review or edits.

Use native selectors, collection/durations and optional workflow_intel test_audit for actual hotspots; static hints are not collection or proof. Review touched tests on each affected candidate, no full-suite audit before every task. For material growth/slow/flaky component, assign scoped cleanup in existing work; no deletion target or audit agent. Focus tests for local work, expand for shared/high-risk/uncertain contracts and explicit current release/CI requirements. Docs-only bookkeeping needs relevant checks, not whole suite by default. Preserve applicable earlier evidence; no test-only release cycle for stale paperwork. Resolve obsolete local blanket rules with current owner authority, not silent waiver.

LLM products: isolate deterministic mechanisms (routing, context, attribution, retrieval, errors, persistence, permission) from stochastic content. Evaluate actual model-dependent objective behavior with representative controlled data, independent rubric/ground truth and disclosed variability. No lucky generation, cherry-picking, exact wording unless required, LLM judgement as ground truth, artificial thresholds or indefinite natural-event waiting. Concrete reproducible defects remain defects; ordinary qualitative long-term behavior observation stays outside development.

Authorized live checks: use actual runtime path on isolated staging/test target with equivalent relevant configuration and representative data. Verify target/account, permission, scope, cost, side effects, isolation and cleanup before action. Never send test messages to real users, write live customer data, spend resources or create accounts without relevant authorization; no secrets in chat/logs/Git. Missing genuinely necessary access: scoped native Human Gate with concrete target, test identity, actions, limits, data and cleanup; retain owner decision in existing project policy, continue independent work. For chat prefer private group and test participant identity; separate instance/test DB or prove isolation of memory/jobs/payments/stats/data, bot-to-bot not assumed equivalent. For others use staging, test stream/payments or disposable dirs/database. No owner routine QA. Essential immediate health/security/correctness proof cannot be deferred simply because inconvenient; if external property objectively inaccessible, report exact gap, do not mark VERIFIED. Safe independent delivery may proceed only with actual independent approval and no reliance on missing proof. No new test platform or mandatory stage.
