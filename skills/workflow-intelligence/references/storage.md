# Workspace hygiene — procedure reference

## One portable workflow-owned storage root and per-check/task/feature housekeeping

**Scope:** all agents, all stacks/projects, local development only. Resolve `<GLOBAL_CONFIG>` from the actual installed global OpenCode configuration containing this AGENTS.md; never hardcode a user, drive, project name, a project-parent path or an OS-specific cache path. All **workflow-created** throwaway data belongs under `<GLOBAL_CONFIG>/WorkspaceData/` (the single owned storage root). New worktree checkouts, disposable Git clones, local backup snapshots, cache/index data, generated probe results, temporary reports, exports, debug logs, screenshots and intermediate files must be created there, or in the current canonical project root **only when they are intentionally durable project source/tests/config/review evidence**. Never create temporary siblings beside the project or under arbitrary home/OS temp paths. A project may be Python, Go, a Minecraft mod, or any other stack.

Use `<GLOBAL_CONFIG>/tools/workflow_housekeeping.py init` once as needed. `allocate` writes under `<GLOBAL_CONFIG>/WorkspaceData/runs/`; `worktree-path` prints a path under `WorkspaceData/worktrees/`. Call `allocate --repo <canonical-project> --epic <stable-epic-id> --unit <stable-task-or-feature-id> --kind probe|temp|report|artifact|cache` for disposable runs, then `worktree-path --repo <canonical-project> --epic <stable-epic-id>` followed by `git worktree add` and `register-worktree --repo ... --epic ... --unit <stable-unit-id> --path ...`. Unit tagging is optional for older allocations; new task/feature allocations MUST tag the owning unit. For checks run inside an existing unit, retain each allocated path to close it immediately after that check. Never invent a unit from the time of day or from a generic working-directory name. Historical `OpenCodeScratch` / `OpenCodeCache` are legacy cleanup targets, not write destinations. Do not copy old scratch into WorkspaceData. The root is the installed config directory plus `WorkspaceData`, overridable only by `OPENCODE_WORKSPACE_DATA`. The bundled global `workflow.intelligence` plugin routes its own index, shell temporary directories and controllable language package caches to WorkspaceData. Where the platform or an external tool unavoidably writes unmanaged system data, disclose the limitation; **do not claim instructions can override every program's native cache or operating-system storage**. Do not rewrite a user's environment globally to enforce this.

**Mandatory per-check, per-task and per-feature cleanup (not epic-only):** Every agent owns the temporary files it creates. Cleanup belongs in the *same normal tool/test completion or specialist handoff*, including failures and `Needs Fixes`, and is not an extra agent, approval, persistent plan or periodic timer. After **each** individual test/probe/browser inspection/screenshot or other one-off check, capture/promote any necessary candidate-bound evidence, ensure the command, browsers, servers and consumers of that exact run have actually ended, then run `run-close --repo <root> --epic <epic> --path <allocated-run-path>` (preview) followed by `run-close ... --confirmed-idle --confirmed-evidence --apply` on positively owned disposable outputs. Use `finally`/native teardown for subprocesses/browser contexts, not time-based deletion. If the test failed or the evidence is still needed for a retry, retain its exact path with reason and next disposition instead of fabricating completion; finish it at the next safe checkpoint. Do not delete logs/screenshots still needed for Reviewer or incident reproduction.

At the completion **of every delegated task, independently accepted fix, feature or slice**, before the agent's existing handoff, the owning agent verifies its task-scoped allocations, failed/interrupted checks and produced workspace paths. Run `unit-close --repo <root> --epic <epic> --unit <stable-unit-id>` (preview), then `unit-close ... --confirmed-idle --confirmed-evidence --apply` when the exact unit's subprocesses/other consumers are finished and necessary evidence was promoted. This removes only matching marked runs and **registered, clean, Git-integrated and inactive task worktrees**; if the task is still under review, will be reused by Builder/Reviewer/DevOps, or contains uncommitted/unique changes, KEEP it until later safe close. Worktrees do not have to survive until the entire epic if their task is conclusively integrated and idle. Do not delete sibling units or shared project caches. At any interruption/retry/re-entry, reconcile previously completed check allocations once as part of normal recovery and safely close them; never delete on age, mere silence, or an unverified `DONE` label. A skipped unsafe cleanup is an explicit retained item, not proof the work itself failed or a new Human Gate.

After **the entire project is genuinely idle**, optional `shared-scratch-close --repo <root>` preview / `shared-scratch-close ... --confirmed-project-idle --confirmed-evidence --apply` clears only the known transient `workflow.intelligence` `tmp/lanes/pycache` children; it intentionally preserves expensive reusable indexes and caches. If any concurrent lane or tool could consume them, keep them. Shared/cache removal is never automatic at task boundaries merely because one worker finished. If an unavoidable third-party tool writes outside the managed root, the owning agent must capture the *exact generated paths and provenance* in the same check and later remove only those individually verified disposable files after their consumers stop and needed evidence is preserved; no recursive wildcard cleanup in OS caches, source trees or home directories. Otherwise retain and report. Other OS/tool caches, historical `OpenCodeScratch`, sibling folders, legacy unmarked directories and unrelated user data are **inventory-only** until proven individually disposable. No universal delete-by-age, folder-name, size or glob.

**Epic close remains a final residual sweep, not the first cleanup:** after all epic children joined, required evidence is promoted, review/release is reconciled and no consumers remain, the responsible Builder/DevOps runs `epic-close --repo ... --epic ... --purge-disposable-cache` in dry-run then `epic-close ... --purge-disposable-cache --confirmed-complete --confirmed-idle --apply` if genuinely safe for this project's shared cache. Keep anything dirty, unique, active, unknown, symlinked, or containing databases/credentials/backups; committed unmerged work is protected via durable refs and may release an unused clean checkout only under the reuse rule below. Every dirty worktree must have a recorded disposition (commit unique changes, preserve a targeted patch, or discard with a justified owner-authorized decision), without wholesale cloning or unreviewed deletion. Never use `git reset --hard`, `git worktree remove --force`, recursive deletion of unknown directories or wiping `plans/`/source/review evidence. The regular specialist handoff must include a **brief housekeeping outcome** (deleted own runs/paths, preserved dependencies, and reason for any skipped cleanup), without another formal report or status ceremony. PM/Orchestrator check for outstanding owned artifacts at the next *normal* handoff and return ownership to the creating agent; do not interrupt unrelated active lanes. No new cleanup-specific subagent or persistent service.

### Cleanup is a checked handoff, not a reminder (mandatory)

This supersedes any earlier wording that treats a successful command, a preview, a prose report, a green product gate, or a deferred epic sweep as proof of cleanup. The code/review/release verdict and local-storage disposition are separate: never falsify or withhold a valid product verdict just to make cleanup green. Orchestrator owns the storage handoff even if a specialist forgot or lost its session.

- At every completed check, close its exact allocated run with `run-close` after joining its own processes and promoting necessary evidence. At each task, corrective slice, feature, accepted review, release handoff, failed/interrupted assignment and normal recovery, reconcile the actual paths that this unit created (including native tool spill outside WorkspaceData). New allocations and worktrees MUST have the stable unit tag, including Reviewer probes and DevOps packaging. No whole-repo copies or copied dependency trees as routine test fixtures. Prefer the existing worktree and existing dependency cache. Do not retain disposable output until epic close. Never treat `KEEP` or a nonzero exit as successful deletion.
- Before releasing a finished unit, execute the existing `unit-close --repo <root> --epic <id> --unit <id> --confirmed-idle --confirmed-evidence --apply` only after its actual consumers join. Then run `unit-check --repo <root> --epic <id> --unit <id>` and read its JSON. Exit 3 means unaccounted remaining paths; `cleanup_complete=false` means bytes/registrations remain, even if `handoff_accounted=true`. Dry-run is not cleanup. A clean scoped check does NOT prove untagged/legacy/external paths were cleaned. Check the creator's exact paths separately. If a path is still needed, record its exact path, owner, specific reason, evidence/consumer and next concrete release event in the existing durable handoff (JSON `cleanup_retained` array, objects with `path`, `owner`, `reason`, `evidence`, `next_event`); pass that existing file with `--retention-file` to `unit-close`/`unit-check`. Explicitly retained items are not deleted. On the recorded event, remove the obsolete retention and retry the exact path after confirming safety. Do not fabricate retention to clear the gate. Missing disposition is a storage handoff defect; Orchestrator must resolve it or assign it to the existing owning lane before reporting the cleanup complete. No new persistent ledger, no new LLM agent, no periodic timer. Independent runnable work and validated release may proceed, but storage debt must stay visible internally until resolved.
- On session recovery and before starting another large allocation, inspect existing known leftover allocations and orphan registrations; use `inventory` for a cross-project read-only view, with `--sizes` only when needed for capacity diagnosis, not every test. It includes managed roots, old untitled runs, worktrees, intelligence scratch/indexes, cache/backups and legacy OpenCodeScratch/OpenCodeCache; it is not authorization to delete. Review actual free disk space (not a sum of apparent file sizes). A low-space/write failure is an operational blocker for *new space-consuming* work, not a reason to kill active processes, discard evidence or change project status. Free known-safe space first; if insufficient, preserve state and use the existing Orchestrator/DevOps lane to resolve. Do not create extra copies or giant reports during space pressure. No fixed size quota or time-based eviction. Keep only the working set genuinely needed for active/queued work, recovery and required evidence, including reusable caches with concrete consumers. Retire idle integrated worktrees and their marked auxiliary scratch/indexes; if ignored files, unique commits, unknown content, locks, links, credentials, DB or evidence are present, resolve their provenance and disposition first. Marked old scratch/cache for retired checkouts that lack a registry, legacy/unmarked/external outputs, and generated dependencies inside otherwise protected trees require exact ownership/consumer checks before targeted cleanup; no blanket delete of Windows TEMP, user cache, source trees or project folders. Ordinary shared scratch remains subject to all-consumers-idle rules.
- No broad recursive deletion, forced worktree removal, Git history rewriting, production cleanup, or arbitrary path deletion by size/name/age. Do not delete files merely because they are ignored by Git. Never delete user-created or unknown data. Report concise actual free-space before/after for a capacity incident; no repeated user-facing cleanup reminders or owner QA requests. If this is an independent retained item, continue the queue without falsely labeling the local cleanup complete.

**One-time legacy cleanup:** user-visible inventory of old sibling folders and historical `OpenCodeCache`/`OpenCodeScratch` first; verify every candidate's provenance, Git registration and branch/commit integration, working-tree dirtiness, ownership and backup uniqueness. Retire safe legacy worktrees with Git, not filesystem deletion. Delete isolated proven-disposable cache and scratch only after confirming no consumer and no unique source/data; preserve uncertain items for review. Never infer deletability from name, age or size. Never access, clean or modify the production server for a local workspace hygiene task. Use the current project root and actual global config, not example absolute paths.

## Reuse before allocation
Before creating a checkout, resolve the existing Ticket/Assignment, Git worktree list and the stable implementation lane. Reuse the same worktree on retries/review corrections/recovery. Reviewer reads an immutable candidate; only allocate a separate checkout for necessary test isolation or a concurrent writer. DevOps reuses a safe clean release checkout if identity and consumers permit. Never switch/reset a live writer. A committed unmerged branch is not by itself a reason to preserve a physical checkout: keep the branch and unique commits, inspect untracked/ignored contents and consumers, and safely remove a clean unused checkout via Git only when recovery remains possible. Existing housekeeping may conservatively refuse; inspect the actual reason and use safe Git removal only with positive ownership, preserved refs/data and no consumers, never --force. Inspect actual files in retained worktrees; a dirty/approved/queued status is not proof that gigabytes of caches are necessary. Scope deletion to individually confirmed disposable agent output, including external spill; preserve unknown files. Do not age-delete, delete based on lack of a process alone, or clear active/paused durable assignments.
